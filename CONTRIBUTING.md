# Contributing to Belqen

Thank you for your interest in contributing to **Belqen**, **Belqen-Kernel**, and **Belqen-OS**.

Belqen is an experimental operating system and kernel project focused on learning, experimentation, and low-level systems development. Contributions, discussions, bug reports, and ideas are welcome as long as they follow the project's rules and license.

## Before Contributing

Before making a contribution, please read:

* [`README.md`](README.md)
* [`LICENSE`](LICENSE)
* [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md)
* [`SECURITY.md`](SECURITY.md)

By contributing to Belqen, you agree to follow the **Belqen Custom Non-Commercial License (BCNCL)** and the applicable project guidelines.

## License Requirements

All contributions must comply with the **Belqen Custom Non-Commercial License (BCNCL)**.

The BCNCL applies to contributions and qualifying derivative works. Contributing to this repository does not grant any additional rights to use, modify, distribute, or process Belqen source code.

Please pay particular attention to the license restrictions concerning:

* Attribution
* Commercial use
* Derivative works
* Redistribution
* License restrictions
* Artificial intelligence processing
* AI-generated source code

If you are unsure whether a proposed contribution complies with the BCNCL, review the [`LICENSE`](LICENSE) before submitting it.

## Source Code Contributions

Belqen's source code is developed by me as a human-written project.

Contributions containing source code must therefore comply with the BCNCL's restrictions regarding artificial intelligence and generated source code.

Do not submit AI-generated source code or modifications to Belqen.

Do not submit source-code changes that were produced through prohibited AI processing of Belqen source code.

If you use development tools, make sure their use does not conflict with the BCNCL.

## What You Can Contribute

Contributions may include:

* Bug fixes
* Kernel improvements
* Operating-system improvements
* Driver improvements
* Hardware support
* Documentation
* Build-system improvements
* Testing
* Debugging information
* Reproduction cases
* Performance investigations
* Ideas and technical discussions

Not every contribution will necessarily be accepted. Belqen is a personal and experimental project, and I may choose the direction of the project.

## Reporting Bugs

Before opening an issue, make sure the problem has not already been reported.

When reporting a bug, provide as much useful information as possible, including:

* What happened
* What you expected to happen
* Steps to reproduce the problem
* Relevant hardware or virtual-machine configuration
* Relevant logs or output
* The affected component
* The affected commit or version, if known

Please do not publicly disclose security vulnerabilities.

For security vulnerabilities, follow the process described in [`SECURITY.md`](SECURITY.md).

## Pull Requests

Before opening a pull request:

1. Make sure your changes are relevant to Belqen.
2. Make sure your changes comply with the BCNCL.
3. Test your changes where reasonably possible.
4. Keep the changes focused.
5. Provide a clear description of what you changed and why.
6. Include relevant testing information.
7. Make sure you have the right to submit the contributed work.

Pull requests may be reviewed, modified, rejected, or closed at my discretion.

## Documentation Contributions

Documentation contributions are welcome.

Documentation should be accurate, clear, and consistent with the existing project documentation.

Documentation must also comply with the BCNCL where applicable.

## Security Contributions

If you discover a potential security vulnerability, please do not create a public issue containing sensitive vulnerability information.

Follow the private reporting process described in [`SECURITY.md`](SECURITY.md).

Security research should only be performed on systems, hardware, networks, or services that you own or have explicit permission to test.

## Contributor Rights

By submitting a contribution, you confirm that:

* You have the right to submit the contribution.
* Your contribution does not knowingly violate another person's rights.
* Your contribution complies with the BCNCL.
* You understand that submitted contributions may become part of Belqen and its qualifying derivative works.

Submitting a contribution does not guarantee that it will be accepted or merged.

## Code Review

Contributions may be reviewed for:

* Correctness
* Stability
* Security
* Compatibility
* Maintainability
* Project consistency
* Compliance with the BCNCL

I may request changes before a contribution can be accepted.

## Questions

If you are unsure about contributing something, please start a Discussion before submitting a pull request.

For security-related questions or vulnerabilities, use the process described in [`SECURITY.md`](SECURITY.md).

Thank you for taking the time to contribute to Belqen.
